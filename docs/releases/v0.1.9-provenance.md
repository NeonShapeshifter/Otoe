## Tag Discrepancy

The `v0.1.9` tag was moved after publication to a later repair commit. Therefore
that tag does not identify the source checkout used by the successful PyPI run.
Moving it again would trigger the historical workflow stored at the old commit
and would further weaken provenance.

The additive tag `pypi-source/v0.1.9` identifies the actual published-source
commit without matching the `v*` publication trigger. The existing release tag
must remain frozen as historical evidence of the incident.

Verify that the additive ref exists remotely when promoting this record:

```bash
git ls-remote origin refs/tags/pypi-source/v0.1.9
git push origin refs/tags/pypi-source/v0.1.9
```

## Forward Remediation

Later releases require an annotated publish marker, a tag target reachable from
`main`, strict typing, coverage and performance gates, reproducible wheel/sdist
checks, exact-artifact smoke tests, checksums, build provenance attestation, and
publication without `skip-existing`. A failed or incorrect release is repaired
with a new version, never a moved tag or replaced artifact.
